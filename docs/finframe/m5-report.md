# FinFrame M5 研究者任务测试：节奏与界面对照（2026-10-09）

这是脚本化的研究者任务测试，**没有真实用户参与**。

**结论**：

1. 三种界面下，Agent 给出第一个有用反馈（第一张预览或取数计划）的时间差不多，Demo A 中位数 8–10 秒。差别来自同一个 Agent 的波动，不是界面造成的。
2. 活报告（C3）在第一张预览出现后再多花约 2.5–4 秒组装界面（Composer）。
3. C3 达成 Demo A 少 1 次操作（3 对 4），而且「看变化最大的年份」是本地点一下、由代码立即给出，不用再等一轮对话（Demo B 第二轮还要约 20 秒）。
4. Composer 回退率 1/8（回退时显示原预览卡）。
5. Demo C 的「平安」在三种界面下 6/6 都被直接当成中国平安，**没有澄清**。这是实体解析的问题，与界面无关，是下一个修复候选。

## 怎么测的

- 原始记录：`eval/finframe/m5/records/2026-10-09T21-42-18-667Z-pacing.json`
- 代码：`eval/finframe/m5/`（commit `f5efa66`）
- 运行时 API：从 `19a9feb` 构建的本机服务（:8711），模型 deepseek-flash。数据是**实时取数**，公司与 snapshot-v1 相同。服务端用真实数据源，没法把快照注入，所以数字层以外的指标不受快照影响。

**条件**：三者用同一个 Agent、同一份提示词和数据，只换布局与开关。

| 条件 | 布局 | 请求开关 |
|---|---|---|
| C1 | 旧双栏画布（对话优先开关关） | `canvas_edit`，加载改画布工具 |
| C2 | 对话优先 + 固定预览卡 | Composer 关 |
| C3 | 对话优先 + 活报告 | `ui_composer` |

**方法**：无头 SSE 重放（`run-pacing.mjs`）。用和界面相同的 `/chat/stream` 接口发脚本里的话，按流事件计时。没有用 Playwright 点界面：流事件就是界面的输入，这样计时更稳定，不受渲染和动画影响。代价是「点击数」要按规则从事件推算（`scripts.mjs`），不是真的点出来的。

**指标**：

- 首个有用反馈：第一张预览（propose_widget 完成）或取数计划的时间。
- 最终布局：C3 是 UI Spec 到达的时间；C1 / C2 是最后一张预览完成的时间。
- 完成：done 事件。
- 操作数：用户发一句话或点一次按钮，各算 1 次。C1 / C2 每张预览要单独点「添加到画布 / 钉住」；C3 一个 ComparisonView 一次钉住它的全部数据集；Demo A 的「变化最大年份」在 C3 有 Spec 高亮动作时是点 1 次，否则要再发一句话。
- Composer 回退率：C3 中有数据集但没收到合规 Spec 的轮数占比。

**样本**：Demo A / B / C × 三种条件 × 2 次，共 18 次运行、24 轮。样本很小，时间只看中位数，差 1–2 秒以内视为没有差别。

**副作用**：本机应用里新建了 18 个标题为「【研究者任务测试】…」的会话，按规则没有删除。

## 解读

- **首个反馈**：主要取决于 Agent 本身（取数和出预览）。三种条件之间相差 1–2 秒，在两次运行的波动范围内。
- **活报告的代价**：Composer 在终答之后、done 之前多一次模型调用，C3 的「最终布局」比首个反馈晚 2.5–4 秒（Demo B 第二轮约 7 秒）。这段时间里用户先看到原预览卡，之后才被替换，所以等待并不是空白屏。
- **活报告的收益**：
  - Demo A 少 1 次钉住：一个对比组件一次钉住两张图。
  - 「变化最大的年份」从「再发一句话、再等一轮」变成「点一下、本地由代码算出」。
  - 每段回答都带 EvidencePanel，来源、报告期、获取时间不用另外点开。
- **Demo C 没达成目标**：
  - 现象：「看一下平安近五年的 ROE」在 C1 / C2 / C3 下 6/6 都直接查了中国平安（601318）。只有 C3 第 2 次在正文里提了一句「如果你指的是平安银行，也可以换过来看」。
  - 位置：生产实体解析（`research-entity-resolver.ts` 的 `pickCnEquityHit`）对「平安」挑出了唯一匹配，模型拿到的就是一个确定的公司，没有机会去澄清。
  - 下一步：按单因素方法，让解析器在简称同时命中多家上市公司时返回「对应多家公司」，再测 Demo C 与 seed-v2 的 v2-19。本次不改。

## 局限

- 样本小（每格 2 次），时间波动大；结论只取方向一致的部分。
- 操作数是按规则推算的，不是真实点击，也没有计入阅读时间。
- 数据是实时取数，不是快照，不同时间重跑数值可能不同。这不影响节奏指标。
