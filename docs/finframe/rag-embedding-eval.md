# 文档知识库：向量模型选型、接入与检索评测方案（2026-10-10）

只分析与方案，未改代码。模型分数来自公开资料，**不能直接互比**，最终以本文第 4 节的自建评测为准。

## 1. 现状（已读代码确认）

| 环节 | 实现 | 位置 |
|---|---|---|
| 解析 | 文本 / Office / PDF 抽取，扫描件 OCR，按页切块，块记录页码 | `packages/doc-library/src/engines/`、`parse-router.ts` |
| 关键词检索 | SQLite FTS5，分词器 `unicode61`，查询为「词*」前缀匹配 | `fts.ts`、`schema.ts` |
| 向量 | `@huggingface/transformers`（ONNX）跑 multilingual-e5-small，384 维，`query:` / `passage:` 前缀；空闲自动卸载 | `embedding.ts`、`paths.ts` |
| 向量库 | LanceDB（chunk_id / document_id / vector(384) / text），坏库自动重建回填 | `vector-store.ts` |
| 融合 | RRF 合并关键词与向量结果 | `hybrid-search.ts`、`rrf.ts` |
| 模型下载 | 内置 → 开发目录 → `~/.opptrix/llms`；源 ModelScope → HF 镜像 → HF | `model-downloader.ts` |
| 调用 | 模型自主调用 4 个工具（列文档 / 库检索 / 文档内检索 / 按页读），回答附页码引用 | `packages/agent/src/document-tools.ts` |

**问题**：

1. **本机向量没开**（启动日志 `embedding=skip`），实际只有关键词检索。
2. **`unicode61` 不切中文**：一串连续汉字是一个词，「毛利率」查不到「年毛利率下降」，中文年报检索基本失效。
3. **模型下载默认在 C 盘用户目录**，C 盘已满。
4. 模型 id 与维度是写死的常量（`EMBEDDING_MODEL_ID` / `EMBEDDING_DIM`），换模型没有迁移路径。
5. **没有任何检索评测**，无法判断哪种配置更好。

## 2. 我们的场景对模型的要求

- **中文金融长文档**：年报、半年报、研报、纪要；术语密集（归母净利润、扣非、毛利率、经营性现金流）；大量表格和数字。
- **本地优先**：用户上传的是自己的资料，默认不出本机；CPU 笔记本、Windows。
- **运行时**：沿用 transformers.js + ONNX（已在用），优先有量化（int8）版本的模型。
- **许可证**：可商用（Apache-2.0 / MIT）。
- **问题形态**：短中文问句（「管理层怎么解释毛利率下降」），常带口语和同义说法（「赚钱能力」≈ 盈利能力）。

## 3. 候选模型

| 模型 | 规模 / 维度 | 中文能力（公开数据） | 许可证 | 本地可行性 | 结论 |
|---|---|---|---|---|---|
| multilingual-e5-small（现用） | 约 1.2 亿参数 / 384 | 多语言通用，中文非强项 | MIT | 小、快 | 基线 |
| bge-small-zh-v1.5 | 小 / 512 | C-MTEB 检索均分 61.77（2023–24 榜单，旧） | MIT | 小、快，只懂中文 | **默认首选候选** |
| bge-m3 | 约 5.7 亿 / 1024，最长 8192 | 多语言，稠密 + 稀疏 + 多向量；未查到 C-MTEB 检索分 | MIT | 偏重，CPU 慢 | 备选 |
| Qwen3-Embedding-0.6B | 0.6B / 1024（可降维） | C-MTEB 综合 66.33（二手来源，未核对官方卡） | Apache-2.0 | 有社区 ONNX 版，int8 约 1.1 GB；需要任务指令前缀 | **高质量档候选** |
| 云端接口（通义 text-embedding、智谱 embedding 等） | — | 通常更强 | 按调用付费 | 资料要上传到云 | 只做可选项，默认关 |

**重排（rerank）**：bge-reranker-v2-m3、Qwen3-Reranker-0.6B 可对前 20 条重排，通常能明显提高前几条的命中率，但每次检索多几百毫秒。是否引入由评测决定。

**初步建议**（待评测验证）：

- 关键词检索换 **trigram 分词**：不依赖模型，中文立刻可用，作为永远在线的底座。
- 默认向量模型换成 **bge-small-zh-v1.5（int8）**：体积小、中文强。
- 提供 **Qwen3-Embedding-0.6B** 作为「高质量」可选档，机器配置够再开。
- 重排先不做，评测证明有显著收益再加。

## 4. 评测方案

分两层：检索层（确定性、可进 CI）和问答层（调真实模型、定期跑）。

### 4.1 检索评测（不调大模型）

- **语料**：5–8 份公开 A 股年报 / 半年报（巨潮资讯网），加 2–3 份公开研报或纪要；覆盖制造、消费、金融，至少一份扫描件。
- **题集**：120 道中文问题，每题标注「标准答案所在页」（可多页）。题型按比例覆盖：
  - 术语 / 指标定位（「研发投入占营收比例在哪里」）
  - 原因解释（「毛利率为什么下降」）
  - 展望与计划（「明年产能计划」）
  - 风险因素
  - 表格定位（「前五大客户」）
  - 同义 / 口语（「赚钱能力怎么样」）
  - 跨文档（「两家公司谁的研发投入多」）
  - **无答案题**（文档里没有，应当检索不到或低分）
- **指标**：Recall@5、Recall@10、MRR@10、nDCG@10、无答案题的误报率；按题型分别统计。
- **成本指标**：每 100 页的入库耗时、单次查询 p50 / p95 延迟（CPU）、内存、磁盘占用。
- **对比配置**：
  1. FTS `unicode61`（现状基线）
  2. FTS trigram
  3. e5-small 单独
  4. bge-small-zh 单独
  5. Qwen3-0.6B 单独
  6. 2 + 4 混合（RRF）
  7. 2 + 5 混合
  8. 6 或 7 再加重排
- **CI 门禁**：从中抽一个小型合成语料（几十个块、20 题），作为确定性的 node 测试进 `test:gate`，防止检索质量回退；完整评测用独立脚本（建议 `npm run eval:rag`），结果存档到 `eval/rag/records/`。

### 4.2 问答评测（调真实模型）

- **题集**：从 4.1 中选 40 题。
- **指标**：
  - 答案正确率：模型打分 + 人工抽检 20%。
  - **引用有效率**：引用的那一页里确实有支持该论断的原文（按页文本自动比对）。
  - **引用格式合规率**：回答里是可点的页码链接，而不是纯文字（本次试跑 5 次中 4 次合规）。
  - **数字规则**：回答里出现的每个数字串，都能在被引用页的原文里找到；文档数字从未传给取数 / 画图工具（检查工具调用参数）。
  - 无答案题能否如实说「文档里没有」。
  - 工具调用次数、端到端耗时。

### 4.3 建议的验收线（评测跑出基线后再定）

| 指标 | 建议目标 |
|---|---|
| 中文题 Recall@10 | ≥ 0.85 |
| 引用有效率 | ≥ 95% |
| 引用格式合规率 | ≥ 95%；达不到就在前端加兜底，把纯文字「《X》第 N 页」识别成可点标记 |
| 数字规则违规 | 0 |
| 单次检索 p95（CPU） | < 800 ms |

## 5. 接入改造（评测选定模型之后）

1. **模型注册表**：把写死的模型 id / 维度改成注册表（id、维度、前缀或指令、池化方式、最大长度）。
2. **向量表按模型隔离**：LanceDB 表名带模型 id 与维度，换模型时新建表并后台回填，旧表保留到回填完成再删；复用现有的重建回填机制。
3. **下载目录可配置**：默认放到数据目录，支持改到 D 盘；沿用 ModelScope 优先的下载源。
4. **trigram 索引迁移**：新增 FTS 表并回填，启动自动、幂等，失败保留旧表（按 AGENTS.md「禁止断代」）。
5. **切块**：保持按页，块大小与重叠由评测调参（建议从 400–600 字、约 15% 重叠起步），表格行尽量不切开，块前加「文件名 · 第 N 页 · 小标题」上下文。
