# FinFrame M4b 笔记：追问报告与版本对比（2026-10-10）

结论：已实现，开关默认关。用户可以引用报告里的一个组件（或像以前一样选中一句话引用），再提问；这次回答会挂到原来那段报告上，成为 v2（再追问就是 v3），v1 原样保留，可以切换版本，也可以把 v1 和选中的版本并排对比。

## 怎么打开

localStorage `finframe.reportFollowup` = `'1'`。只在对话优先布局且 Composer 开启时生效（与 `finframe.composer` 同一层级）。关闭时界面与 M4 完全一致。

## 怎么工作

1. **引用组件**：每个 Spec 组件下方多一个「追问这部分」。点了以后，走现有「选中文字 → 引用」的同一条路径（`onQuoteSelection` → 会话引用），引用内容是组件的标题、公司、指标、期间，**不带任何数值**。
2. **引用句子**：沿用原有的选中文字工具条「引用」，没有改。
3. **记录追问关系**：发送时，如果开关开、且当前引用来自一段回答，就在本浏览器记一条「追问原文 → 被引用回答的时间戳」（`finframe.reportFollowups.<会话>`，最多 50 条）。
4. **对上版本**：渲染时按时间戳找到原回答，再找它之后第一条原文相同的提问，提问后的那条回答就是新版本。对不上（会话被分叉、编辑过）就忽略，界面退回 M4 的样子。
5. **显示**：
   - 原回答处出现「报告版本」一栏：v1 原始、v2 追问：…、并排对比。默认显示最新一版。
   - 每一版都用那一轮自己的步骤和 Spec 渲染，钉住、查看来源等动作也用那一轮的提案。
   - 追问那一轮自己照常显示，顶上加一句「已记为上方报告的 v2」和「回到那段报告」。
   - 某一版没有图表时，说明文字回答在下方追问那段里。

## 选择与备选

| 分岔 | 选了 | 备选 | 理由 |
|---|---|---|---|
| 追问关系存哪 | A：只存本浏览器（与数据集一致） | B：请求体加字段，服务端写进合成步骤，跨设备可见 | A 不改接口和会话存储；数据集本来就只在本浏览器，换设备时报告本身也会回退到预览卡 |
| 新版本放哪 | 挂到原回答上，追问那轮照常保留 | 把追问那轮的报告隐藏、只在原处显示 | 保留更不容易让人困惑；流式时那一轮本来就要显示 |
| 并排对比 | v1 对选中的版本（选中 v1 时对最新一版） | 任意两版自选 | 先满足「新旧对比」，界面更简单 |
| 组件追问入口 | 组件下方一个按钮，不进 Spec | 做成 Spec 动作，由模型决定是否出现 | 追问是界面能力，不该让模型决定；也不用改 Spec 协议 |

## 未做 / 已知

- 引用在会话里会一直生效，直到用户手动移除。所以引用一段报告后连续提问，每一问都会记成新版本（v2、v3…）。这和现有「引用」的语义一致，但可能多于用户预期。
- 换浏览器或清空本地存储后，版本关系丢失，各轮回答仍各自正常显示。
- 没有用真实用户或真实模型做端到端验收。
