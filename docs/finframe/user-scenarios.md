# FinFrame 用户场景、需求与典型流程（2026-10-10）

起点：Quinn 问「我要是就为了查个数，为什么要用 agent？」

## 结论

- **只查一个数，确实不需要 agent。** 同花顺 F10、东方财富个股页、搜索引擎打开就有，一两秒。FinFrame 如果查一个数要等 10 秒、还要看一段过程，会输。
- **agent 的价值在「一个数之后的那几步」**：对齐口径、拉多家多年、比较、算变化、找原因、整理成能用的图表和结论，并且每个数能核对。这些在传统工具里是「开五个页面、抄进 Excel、自己画图」。
- **所以产品要分两条路**：
  1. **查数快路**：识别出「某公司某年某指标」这类单点问题，直接取数、直接给答案卡（数字、来源、口径），不跑多轮推理、不组装活报告，目标 3 秒内。
  2. **研究慢路**：比较、速览、追问原因、整理成报告，才走 agent 和活报告。
- 查数快路本身也是入口：答案卡下面一句「要不要和同行比一下 / 看看近五年走势」由用户在对话里接着说，自然进入研究慢路。

## 用户是谁

| 用户 | 典型需求 | 现有替代 | 痛点 |
|---|---|---|---|
| 自己做研究的个人投资者 | 看一家公司在变好还是变坏、和同行比 | 同花顺 / 东财个股页、F10 | 多家多年要来回切页面，口径看不懂 |
| 写作者（财经号、博主、研报助理） | 要一张干净、带来源的对比图放进文章 | 手抄数据进 Excel 画图 | 费时，来源和口径容易写错 |
| 研究员 / 投顾 | 快速核对一个说法、给客户解释 | Wind / iFinD（贵）、手工 | 临时问题成本高，解释材料要重新做 |

## 典型场景与流程

| # | 场景 | 用户一句话 | 期望的流程 | 是否需要 agent |
|---|---|---|---|---|
| 1 | **核一个数** | 「茅台 2024 年 ROE 多少」 | 直接出答案卡：数字 + 年报出处 + 口径；1–3 秒 | 不需要，走快路 |
| 2 | **看一家公司** | 「看看宁德时代」 | 取 5 个核心指标 → 结论 + 指标卡 + 走势 + 要点 + 数值表 | 需要（选指标、组织页面） |
| 3 | **比较** | 「茅台和五粮液近五年毛利率」 | 对齐年份与口径 → 对比图 + 差距结论 | 需要（对齐、缺失处理） |
| 4 | **同行排位** | 「白酒行业谁的 ROE 最高」 | 确认公司名单 → 排名 + 中位数 | 需要（圈定同行、确认名单） |
| 5 | **追问原因** | 「为什么净利率下降了」 | 拆成毛利率、费用率等 → 变化拆解 | 需要（选拆解路径） |
| 6 | **整理与分享** | 「把这张图钉住 / 导出」 | 钉进看板 → 导出带来源的图 | 不需要模型，界面完成 |
| 7 | **回头看** | 打开看板 | 新财报出来后看到「哪些数变了」 | 不需要模型，代码完成 |

一个完整流程通常是 1 → 3 或 2 → 5 → 6：先核一个数，觉得有意思再比、再问为什么，最后留下一张能用的图。

## 对产品的要求（按优先级）

1. **查数快路（P0）**：单公司、单指标、单年份（或「最新」）的问题，不进多轮工具循环，直接返回答案卡。实现上可以先用规则识别句式，再走现有 `query_data`，跳过 Composer。需要先出方案（涉及 agent 流程）。
2. **回答要比翻页面省事（P0）**：比较类问题一次给全（对齐年份、口径、缺失说明），不让用户再问第二句才拿到能用的结果。
3. **结果能带走（P1）**：导出的图自带来源和口径脚注（之前列为未做）。
4. **从答案卡自然进入研究（P1）**：不加按钮，用一句提示引导「可以接着问：和同行比一下」。
5. **衡量标准**：和「打开同花顺查」比，核一个数不慢于 3 秒；做一次两家五年的比较，操作数和耗时明显少于手工（M5 的方法可以复用）。

## 不做的

- 用 agent 回答所有问题。查价格、查单个数这类问题，越快越好，不需要「思考过程」。
- 让模型去写数字或给买卖建议。
