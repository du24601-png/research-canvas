# FinFrame M2 报告：Agent 策略单因素实验（2026-10-09）

结论：四个实验都保留。

| 实验 | 结果 |
|---|---|
| E3（美港股快速失败） | 效果最大最确定：ff-012 的工具调用从每次 10–14 次降到 1 次 |
| E2（代码给出走势标签） | 与数据相反的走势说法从对照组的 3/7、2/3 降到 0；模型开始纠正用户问题里的错误前提 |
| E1（正文不写数字） | 真实编造数字从对照的 1/2 次运行降到 0/2 次，信号弱，但方向一致、无回退 |
| E4（改画布三件套改为可选包） | 改后的两个目标题都通过，其他层没有一致回退 |

E0 说明 M4 的 pl-023 下降更像波动，而不是冻结清单的改动造成的。

**方法**：按简报 §4.7，每个实验走「失败 → 假设 → 一处改动 → 数据 → 结论」，每组测 seed ×2 + planning ×2 + prompt ×2。模型 deepseek-flash，temperature 0。只和 M2 对照组比较（`0f2d785` 修好夹具之后），不与修复前的 M1–M4 种子分数混合。根因只写「假设」，不写成已证实。

**噪声**：temperature 0 下单题仍有波动。对照组两次 prompt 是 23/24 与 20/24，相差 3 题；planning 在完全不受 E1 影响的情况下也有 22–24 的波动。两次运行只能看出大的效果，小差异都标为「不确定」。

### E0（诊断，不改产品）：pl-023 的下降是不是冻结清单改动造成的

- 做法：只把冻结评测清单里的 yoy_delta 临时去掉，跑 planning ×2，之后恢复（`abbcbed` 记录）。
- 结果：去掉后 24/24、24/24。带着 yoy_delta 的六次运行里，pl-023 失败 2 次（都在 M4），通过 4 次（对照两次、E2 两次）。
- 结论：没有证据说明是清单改动造成的，更像波动；两次运行排除不了小的影响。

### E1（F2 / data_missing）：正文里的数字从哪来

- 失败：M1 F2 记录了「茅台 50% 左右」「两家都在 20% 上下」这类数据集里没有的数字。
- 假设（未证实）：playbook 要求正文写「关键数字与口径」，而模型从工具结果里看不到任何数值，于是用记忆补。
- 改动：只改 playbook 措辞。不再要求写关键数字；明确「你看不到数值，正文不得写任何具体数字、区间、约数或估计」；不支持的指标要直接说查不到、列出可查的相近指标让用户选，然后停下。
- 数据：真实编造数字（人工核对过评分器报出的每一条）：对照组第 1 次运行 ff-007 写了「宁德时代大致在 20% 上下……24%–25% 附近」等 7 个无据数字，第 2 次 0；E1 两次都是 0。prompt 层的 pl-023（净息差）对照两次失败，E1 两次通过。planning 层的 pl-023 在 E1 两次失败，但 planning 用的是评测专用短提示词、不受 E1 影响，属于波动。
- 结论：**保留**。方向一致、没有回退，但两次运行的信号弱。
- 附带：E1 改写措辞后，`tests/agent-research-prompt.test.mjs`（不在门禁里）里一条匹配「禁止用净利率」的断言失效，E4 时一并修了。

### E2（F3 / 走势说法没有依据）

- 失败：M1 F3 记录了「海天 ROE 逐级下台阶、2024 为区间低点」这类与数据相反的说法。
- 假设（未证实）：工具结果里没有数值，模型就按对公司的印象，或按用户问题里的前提，描述走势。
- 改动：`describeDatasetForModel` 给每家公司附代码算的标签：上升 / 下降 / 基本持平 / 波动 / 数据不足，最高年份、最低年份、缺数年份，不含数值；再加一句 trend_note「描述走势只能依据 trends」。没有选的另一种做法：在 playbook 里禁止一切方向性说法。
- 数据：粗略自动检查（一句话里只点名一家公司且带方向词，与代码标签比对，只记明显相反的）：对照组 3/7、2/3 相反；E1 1/1、0/0；E2 0/5、0/8；之后 E3、E4 也都是 0。人工抽查 ff-005：用户问「ROE 为什么下滑」，而数据其实是先降后升。E2 的回答写明「并不是一路单边下滑：区间低点在 2022 年……2024 年是这五年里最高」，并把能证实的和待核实的分开写；对照组顺着用户的前提写成了「一路下台阶」。
- 结论：**保留**。这是效果最清楚的一项。
- 注意：`research-query-data.ts` 原有 485 行，加了 3 行（原本就超长）。

### E3（F1 / 美港股反复重试）

- 失败：M1 F1 记录了 ff-012（苹果、腾讯）每次 8–10 次调用，含被禁止的网页搜索。
- 假设（未证实）：通用错误「无法确认…对应的上市公司」读起来像名称写错了，模型就换写法、换工具反复试。
- 改动：实体解析在代码明确属于美股 / 港股，或搜索只命中非 A 股时，返回 `status: unsupported_market`，并附上市场和 hint；playbook 加一条「照实告诉用户只支持 A 股并停下」。种子夹具同步返回同样的结果。
- 数据：ff-012 工具调用次数，对照 11、14，E1 13、10，E2 13、10，E3 和 E4 都是 1；对照和 E1 各有一次调用了被禁止的网页搜索，E3 之后没有。refusal 从 10 升到 11（剩下的失败只有 ff-009）。prompt 层是 21、22（E2 是 23、23），但失败题 pl-007 / pl-009 / pl-020 / pl-015 和美港股无关，对照组自己也在 20–23 之间，**不能归因于 E3**。
- 结论：**保留**。

### E4（AI 不改看板）

- 动机：原则 3 已改为「AI 不得往看板写东西」，M3a 只在前端忽略了 widget_created。
- 改动：三个工具移到可选包 `research_canvas_edit`（仍注册，optIn，目前没有打开的入口）。playbook 和证据纪律里相关的规则与顺带提及，在没加载该包时全部去掉，改为「看板只由用户操作：加图请用户点钉住；换图种就再提新预览」。路由计划里「加一个…图」「改成折线图」首选改为 propose_widget。评测侧：冻结清单删掉这三个工具（记为 `retired_tools`，用例里禁止它们的约束仍然有效）；pl-017 的 gold 从 create_widget 改为不调工具，pl-018 的 gold 从 update_widget 改为对同一数据集 propose_widget；评测专用 planning 提示词和画布元数据行同步。
- 数据：pl-017 / pl-018 在新 gold 下四次运行全部通过。planning 是 24、21：第 2 次失败的 pl-005 / pl-007 / pl-023 都是反复波动的题；其中 pl-005 第一次出现失败（先问用户、没先取数），可能和评测提示词的改动有关，**未证实**。prompt 是 23、22，没有新失败题。
- 结论：**保留**。
- 已知代价：旧双栏布局（开关关闭）也失去了「AI 改右侧已有图」的能力。这个可选包目前没有打开的入口，需要的话后续给旧布局加一个开关。

## 评分器修正（M2 期间，存档未改，已统一重算）

- numbers_grounded 不再把下列内容当成数值断言：
  - 「每 100 元」「每投入 100 元」这类解释口径的单位量；
  - 覆盖度计数（如 10/10，来自工具的 coverage 字段）；
  - 月份区间（3–4 月）；
  - 英文计数（5 years）；
  - 「共 5 个」这类计数。
  改动前，E1 的 ff-001 / ff-005 被误判为编造。
- refusal 加入「没法 / 做不了 / 不在…范围」。改动前，E4 两次 ff-012 正确的拒绝被漏判。
- 修复中发现评分器里的 `\b` 被写成了不可见的退格字符，已修正，并加了测试。
