02 · 分工

模型看不到数值，所以写不了数字

模型看不到数值，只能按代码给的「上升 / 下降 / 波动」写话。早期要求正文写数字时，对照组一次写出 7 个数据里没有的数；改规则后，两次运行都是 0。

模型

负责理解和表达
  • 听懂问题，决定查哪家公司、哪个指标、哪几年
  • 选合适的图：对比、走势、表格
  • 按代码给的走势标签写解读
  • 不写具体数字（它根本看不到数值）
  • 不直接画图，不直接写进看板

代码

负责每一个数字
  • 从数据源取回每个财务数字，记来源和报告期
  • 同比变化等衍生数由代码算
  • 算走势标签：上升、下降、最高年份、缺数年份
  • 校验报告格式，不合规就退回
  • 缺数显示「—」，不当成 0

用户

负责判断和确认
  • 决定一张图留不留（点「钉住」）
  • 有歧义时做选择，比如「平安」指哪家
  • 决定下一步问什么、怎么改图
  • 系统不替用户下买卖结论
7→0

为什么要这样分：早期规则要求「正文写关键数字」，模型看不到数值就凭记忆补。对照组跑两次，其中一次写出了 7 个数据里根本没有的数字。改成「正文不写数字、走势只按代码标签说」之后，两次运行都是 0；走势说反的情况也从 3/7 降到 0。

可能被追问「为什么不……」
为什么不直接用 RAGFlow 或 Dify？有记录它们要多一套 Python 服务和 Elasticsearch 这类依赖，和我们本机、轻量、Node 的部署方式冲突；而且我们的页码引用、数字溯源要重新对接。有几个项目的许可证限制商用或有传染性，所以只学思路、不拷代码。借鉴的点包括：RRF 融合、最低相关度、重排失败自动回退。
为什么不用 Elasticsearch、Milvus、pgvector？通用理由个人级资料量（几份到几百份年报）不需要分布式检索服务；SQLite 和 LanceDB 都是嵌入式的，就是磁盘上的文件，部署零运维。代价是数据量很大时扩展性不如独立服务。
为什么选 LanceDB，不选 FAISS 或 Chroma？通用理由LanceDB 能在 Node 里直接用、数据落盘、按表管理（我们每个向量模型一张表）。坦白说没有做过向量库之间的对比评测。
为什么让模型自己调检索工具？通用理由投研对话里很多问题根本不需要查年报，每次都检索会浪费上下文、还会塞进无关片段；让模型决定，它也能根据第一次结果再翻具体页。代价是模型可能漏掉该检索的时候，所以提示词里写了文档引用规则。
文档里的数字能拿去画图吗？有记录不能。规则规定文档里的数字只作原文摘录，不进取数和画图工具，避免把没核对过的数当成结构化数据。
已经上传的旧文档会用新切法吗？有记录不会，只有新上传的受益。重建要改用户已有数据，按项目规则要先确认，还没做。
答不上时：「检索代码在 packages/doc-library，调研和评测报告在 docs/finframe/rag-oss-survey.md、rag-eval-report-v2.md。我可以打开评测数据给您看每个选择的前后对比。」
04 · 混合检索

两路一起查，只按名次合并

关键词精确但不会换说法，向量能换说法但会带回无关段落。两路名单用 RRF 只按名次合并，不用把两种分数加权。原话问法混合是 0.67，高于只用向量的 0.62；关键词问法是 0.96，高于 0.83。

按字找中文三字切片（trigram）

年毛利率下降→年毛利毛利率利率下率下降

旧分词把一串连续汉字当成一个词，搜「毛利率」找不到「年毛利率下降」，中文检索基本失效。改成每三个字切一片，不需要词典和模型。整句问题也切成三字片段，至少命中 2 个且不少于 30% 才算。

按意思找向量检索

本机小模型把每段文字变成一串数字，意思接近的段落数字也接近。用户不用年报原词也能找到，比如问「赚钱能力」，找到写「盈利能力」的段落。

合并：RRF，只看名次 得分 = Σ 1 / (60 + 名次)

段落甲：关键词第 1、向量第 31/61 + 1/63 = 0.0323
段落乙：只在向量里排第 11/61 = 0.0164

两边都靠前的排最前。不用比较两种分数的大小，也就不用调权重。

可能被追问「为什么不……」
为什么不用 jieba 这类中文分词？通用理由三字切片不需要词典，金融长词、新词（比如「扣非归母净利润」）不在词典里也能切到；SQLite 内置支持，零依赖。代价是索引更大：新索引 12.4 MB，旧的 6.3 MB有记录。项目里没有和 jieba 做过对比。
为什么用 RRF，不用加权求和？有记录关键词给的是 BM25 分，向量给的是相似度，刻度完全不同，直接相加要反复调权重。RAGFlow 用的是加权（默认关键词 0.7、向量 0.3），FastGPT 用 RRF。我们选 RRF，因为不用调参、对分数分布不敏感。
k 为什么是 60？通用理由这是提出 RRF 的论文和多数实现的默认值，作用是让第 1 名和第 5 名的差距不要太悬殊。我们没有专门调这个参数。
只用向量不就够了吗？有记录看图：只用向量在两种问法下都比混合低。年报里大量精确术语和数字，关键词更可靠。
原话问法为什么只有 0.67？有记录用户原话和年报措辞差距大，「同义口语」题只用向量时只有 0.25。改进方向是加重排模型，或者先让模型把问题改写成关键词，这也是 Agent 现在自己在做的事。

可能被追问「为什么不……」
不用框架，不是重复造轮子吗？有记录核心循环本身不复杂；复杂的是围绕它的控制：会话级工具冻结、可选包、最后一轮禁工具、压缩、事件流。这些用框架也得自己写，还要绕开框架的默认行为。
为什么不用 LangGraph 的状态图？通用理由状态图适合固定的多步流程，比如审批流。我们的主路径就是一个循环加几道护栏，下一步做什么交给模型决定，画成状态图是过度设计。
为什么不用 Vercel AI SDK？有记录它的前端 hook 绑定自己的服务端流格式，我们服务端是自研引擎，事件类型也是自定义的，要改的是整个接口层。
前缀缓存是什么？有记录模型服务会缓存请求开头相同的部分，下一次请求开头一样就不用重新算，更快也更便宜。工具定义很长、放在最前面，如果每轮工具顺序或集合变了，缓存就失效。代码注释写明了冻结就是为了这个。
为什么不做多 Agent？通用理由多 Agent 适合任务能拆成独立子任务的场景。投研提问通常是「取数、出图、解读」一条线，拆开反而要在 Agent 之间传上下文，延迟和出错点都会增加，评测也更难定位。
原生工具调用有什么缺点？通用理由依赖模型和服务商的支持程度，不同服务商对参数的支持不一样，所以我们做了自动降级。
MCP 用了吗？有记录支持，用官方 SDK，可以外接工具；主路径的工具都在进程内，不走 MCP。

不合规的是什么问题？有记录30 题场景集里的几次失败，是输出不是合法 JSON，或者给不该带动作的组件加了动作。都被校验拦住、退回了预览卡。首次接入时那 5 次的具体原因我没有逐条整理。
为什么报告描述存成一个「合成步骤」？有记录有两个方案：一是作为一个合成的工具步骤写进历史，不改会话存储格式；二是在消息上加新字段，要改存储格式。选了一，因为项目规则是存储格式只增不破，而且历史回放和实时看到的完全一致。
「钉住」为什么不让 AI 自动做？有记录看板是用户自己的研究成果，AI 只能提议。这样用户永远知道看板里每张图是自己确认过的。
「派生新数据集」是什么意思？有记录数据集不可改。比如算同比变化，会生成一个新数据集，记下它来自哪个父数据集、做了什么变换。这样任何一个数都能追溯回原始取数。
